# 文档编写建议

写好技术文档的一些经验总结。

## 基本原则

### 先想清楚再写

写之前先问自己三个问题：

- **给谁看？** — 自己复习，还是给别人看？
- **写什么？** — 核心知识点是什么？
- **怎么用？** — 未来会怎么查阅这篇文章？

### 结构先行

好文章的关键在于**清晰的结构**。

```md
# 标题（一句话说清主题）

## 概述（2-3 句话介绍）

## 核心内容 1

## 核心内容 2

## 总结
```

### 一层一层递进

- **h1** = 文章主题，一篇文章一个就够了
- **h2** = 大章节，3-6 个为宜
- **h3** = 细节展开，按需使用

## 内容规范

### 多用列表，少写长段落

长段落阅读体验差，尽量拆成列表：

```md
<!-- ✗ 不好 -->
安装 JDK 需要先去官网下载对应版本的安装包，然后双击安装，安装过程中注意选择安装路径不要有中文。

<!-- ✓ 好 -->
1. 访问 Oracle 官网下载 JDK
2. 双击安装包运行
3. 选择安装路径（避免中文和空格）
4. 完成安装
```

### 善用表格

对比类内容用表格比文字清楚得多：

```md
| 功能 | 方案A | 方案B |
|------|-------|-------|
| 性能 | 高 | 中 |
| 成本 | 免费 | 付费 |
```

### 代码块标注语言

````md
```java          ← 标注语言，开启语法高亮
public class ...
```
````

### 配图原则

- 截图不要太模糊
- 标注关键区域（红框、箭头）
- 图片不要太大，宽度 800px 以内

## 格式建议

| 场景 | 用法 |
|------|------|
| 菜单路径 | **文件** → **设置** → **插件** |
| 按钮名 | 点击 **确定** |
| 文件名 | `application.yml` |
| 快捷键 | `Ctrl + Shift + P` |
| 强调 | **重点内容用粗体** |

## 自查清单

写完文章后检查：

- [ ] 标题反映了文章主题吗？
- [ ] 步骤可以复现吗？
- [ ] 代码有没有标注语言？
- [ ] 外部链接打不打得开？
- [ ] 有没有错别字？
