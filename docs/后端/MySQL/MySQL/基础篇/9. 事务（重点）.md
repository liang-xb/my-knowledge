# MySQL 事务

---

## 基本介绍

事务用于保证数据的一致性，它由 **一组相关的 DML 语句组成**，该组的 DML 语句 **要么全部成功，要么全部失败**。举例：转账就要用事务来处理，用以保证数据的一致性。

![事务示意图](事务示意图.png)

当 **执行事务** 操作时（DML 语句），MySQL 会在表上 **加锁**，防止其他用户改变表的数据。

## 事务的前提

**执行事务的前提：INNODB 引擎**

## 事务操作

![事务操作](事务操作.png)

`START TRANSACTION = SET autocommit=off`

### 操作案例

```sql
# 创建表
CREATE TABLE table01(
  id INT AUTO_INCREMENT PRIMARY KEY,
  `name` VARCHAR(32)
);

START TRANSACTION;                      -- 开启事务

INSERT INTO table01 (id,`name`) VALUES(1,'jack');

SAVEPOINT a;                            -- 建立保存点 a

INSERT INTO table01(id,`name`) VALUES(NULL,'tom');

SAVEPOINT b;                            -- 建立保存点 b

ROLLBACK TO a;                          -- 回退到保存点 a

COMMIT;                                 -- 提交，不可回退
```

### 回退事务

保存点（SAVEPOINT）是事务中的一个点，用于取消部分事务。当结束事务（COMMIT）时，会自动删除事务定义的所有保存点。当执行回退事务时，通过指定保存点可以回退到指定的点。

### 提交事务

使用 COMMIT 语句可以提交事务。当执行了 COMMIT 语句后，会确认事务的变化、结束事务、删除保存点、释放锁、数据生效。当使用 COMMIT 语句结束事务后，其他会话将可以看到事务变化后的新数据。

## 事务隔离级别

### 基本介绍

1. 多个连接 **开启各自事务** 操作数据库中数据时，数据库系统要负责 **隔离** 操作，以 **保证** 各个连接在 **获取数据** 时的 **准确性**
2. 事务隔离级别越高，数据越安全，但是性能越低
3. 隔离级别是 **跟事务相关的**，首先得启动事务
4. 如果不考虑隔离，可能会引发 **脏读、不可重复读、幻读** 的问题

### 并发事务问题

**脏读（Dirty Read）：** 一个事务读到另外一个事务还没有提交的数据。

<img src="./脏读.png" style="width:800px;margin:0 auto;" />

**不可重复读（Nonrepeatable Read）：** 一个事务先后读取同一条记录，但两次读取的数据不同。

<img src="./不可重复读.png" style="width:800px;margin:0 auto;" />

**幻读（Phantom Read）：** 一个事务按照条件查询数据时，没有对应的数据行，但是在插入数据时，又发现这行数据已经存在，好像出现了"幻影"。

<img src="./幻读.png" style="width:800px;margin:0 auto;" />

### 四种隔离级别

![隔离级别](隔离级别.png)

> 注意：**加锁** 后，需要等 **事务 COMMIT 后才会读取内容**，**否则** 会处于 **阻塞** 状态。

### 查看隔离级别

```sql
-- 查看当前会话隔离级别
SELECT @@TRANSACTION_ISOLATION;

-- 查看全局隔离级别
SELECT @@GLOBAL.TRANSACTION_ISOLATION;
```

### 设置隔离级别

隔离级别：READ UNCOMMITTED、READ COMMITTED、REPEATABLE READ、SERIALIZABLE

```sql
SET [SESSION | GLOBAL] TRANSACTION ISOLATION LEVEL
{ READ UNCOMMITTED | READ COMMITTED | REPEATABLE READ | SERIALIZABLE }
```

### 修改默认隔离级别

默认 MySQL 的事务是自动提交的（**默认隔离级别：REPEATABLE READ**），也就是说，当执行完一条 DML 语句时，MySQL 会立即隐式地提交事务。

一般情况下，没有特殊要求，没有必要修改，默认级别能够满足大部分项目需求。

修改方法：打开 **.ini** 配置文件，添加如下指令（可选参数：READ-UNCOMMITTED、READ-COMMITTED、REPEATABLE-READ、SERIALIZABLE，**要带中间的一个横杠**）。

```
transaction-isolation = REPEATABLE-READ
```
