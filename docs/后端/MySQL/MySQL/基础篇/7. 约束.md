---

![约束类型表](约束类型表.png)

## PRIMARY KEY

### 基本介绍

用于表行的数据的 **唯一标识**，当定义主键约束后，**该列不能重复**。

语法：`字段名 字段类型 PRIMARY KEY`

### 使用细节

1. PRIMARY KEY **不能重复且不能为 NULL**
2. 一张表 **最多只能有一个主键**，**但可以是复合主键**
3. 主键的指定方式有两种：
   - 直接在字段名后指定：`字段名 PRIMARY KEY`
   - 在表定义最后写：`PRIMARY KEY(列名)`
4. 使用 `DESC 表名`，可以看到 PRIMARY KEY 的情况
5. 在实际开发中，每个表往往会设计一个主键

```sql
-- id  name  email
CREATE TABLE t17
(
    id INT PRIMARY KEY, -- 表示 id 列是主键
    `name` VARCHAR(32),
    email VARCHAR(32)
);

-- 主键列的值不可重复
INSERT INTO t17 VALUES(1, 'jack', 'jack@sohu.com');
INSERT INTO t17 VALUES(2, 'tom', 'tom@sohu.com');
INSERT INTO t17 VALUES(1, 'hsp', 'hsp@sohu.com'); -- 违背了主键（id相同）
```

### 复合主键

> 注意：使用复合主键时，只有当复合主键值 **全部相同** 才会违反规则。

```sql
CREATE TABLE t18
(
    id INT,
    `name` VARCHAR(32),
    email VARCHAR(32),
    PRIMARY KEY (id, `name`) -- 复合主键
);

INSERT INTO t18 VALUES(1, 'tom', 'tom@sohu.com');
INSERT INTO t18 VALUES(1, 'jack', 'jack@sohu.com');
INSERT INTO t18 VALUES(1, 'tom', 'xx@sohu.com'); -- 违反复合主键（id、name相同）

SELECT * FROM t18;
```

## NOT NULL

如果指定了字段非空，即 **字段值非空**，则在添加数据时必须给这个字段添加数据。

语法：`字段名 字段类型 NOT NULL`

```sql
CREATE TABLE mytable
(
    id INT NOT NULL,
    name VARCHAR(32)
);
```

## UNIQUE

当定义了唯一约束后，**该列值是不能重复的**。

语法：`字段名 字段类型 UNIQUE`

**使用细节：**

1. 如果没有指定 NOT NULL，则 UNIQUE 字段 **可以有多个 NULL**
2. 一张表 **可以有多个 UNIQUE 字段**

## 外键约束

### 基本介绍

![外键约束示意图](外键约束示意图.png)

外键用来让两张表的数据之间建立连接，从而 **保证数据的一致性和完整性**。

用于定义主表和从表之间的关系：外键约束要定义在从表上，**主表** 则 **必须有主键约束或是 UNIQUE 约束**。当定义外键约束后，要求外键列数据必须在主表的主键列存在或是为 NULL。

- **主表**：班级表（约束方）
- **从表**：学生表（被约束方）

### 基本语法

```sql
-- 创建表时指定
CREATE TABLE 表名(
    字段名 数据类型,
    ...
    [CONSTRAINT] [外键名称] FOREIGN KEY 子表(外键字段名) REFERENCES 主表(主表列名)
);

-- 建完表后添加外键
ALTER TABLE 表名 ADD CONSTRAINT 外键名称 FOREIGN KEY 子表(外键字段名) REFERENCES 主表(主表列名);
```

### 使用细节

1. 外键指向的表的字段，要么是 **PRIMARY KEY 或者是 UNIQUE**
2. **表的类型必须是 INNODB**，这样的表才支持外键
3. **外键** 字段的类型跟 **主键** 字段的 **类型一致**（长度可以不同）
4. **外键字段的值，必须在主键字段中出现过，或者为 NULL（前提是外键字段允许 NULL）**
5. 一旦建立外键的关系，**数据不能随意删除**

### 删除/更新行为

![约束行为](约束行为.png)

**CASCADE：**

```sql
ALTER TABLE 表名 ADD CONSTRAINT 外键名称 FOREIGN KEY (外键字段) REFERENCES
主表名 (主表字段名) ON UPDATE CASCADE ON DELETE CASCADE;
```

**SET NULL：**

```sql
ALTER TABLE emp ADD CONSTRAINT fk_emp_dept_id FOREIGN KEY (dept_id) REFERENCES
dept(id) ON UPDATE SET NULL ON DELETE SET NULL;
```

### 物理外键与逻辑外键

**物理外键：** 使用 FOREIGN KEY 定义外键关联另外一张表。

缺点：
- 影响增、删、改的效率（需要检查外键关系）
- 仅用于单节点数据库，不适用于分布式、集群场景
- 容易引发数据库的死锁问题，消耗性能

**逻辑外键：** 在业务逻辑层中解决外键关联。

::: tip 温馨提示
在现在的 **企业开发** 中，很少会使用物理外键，都是使用 **逻辑外键**。甚至在一些数据库开发规范中，会明确指出禁止使用物理外键 FOREIGN KEY。
:::

## CHECK

### 基本介绍

**用于强制执行数据必须满足的条件**。假定在 sal 列上定义了 CHECK 约束，并要求 sal 值在 1000 ~ 2000 之间，如果不在范围内就会提示错误。

语法：`列名 类型 CHECK（条件）`

```sql
CREATE TABLE t23 (
  id INT PRIMARY KEY,
  `name` VARCHAR(32),
  sex VARCHAR(6) CHECK (sex IN('man','woman')),
  sal DOUBLE CHECK (sal > 1000 AND sal < 2000)
);
```

> Oracle 和 SQL Server 都支持 CHECK，但是 **MySQL5.7** 目前还不支持 CHECK，只做语法校验，但 **不会生效**。

## 约束建表练习

![约束建表练习](约束建表练习.png)

```sql
CREATE DATABASE shop_db;

-- 现有一个商店的数据库 shop_db，记录客户及其购物情况，包含以下三个表：
-- 商品 goods (goods_id, goods_name, unitprice, category, provider)
-- 客户 customer (customer_id, name, address, email, sex, card_ID)
-- 购买 purchase (order_id, customer_id, goods_id, nums)

-- 商品 goods
CREATE TABLE goods (
    goods_id INT PRIMARY KEY,
    goods_name VARCHAR(64) NOT NULL DEFAULT "",
    unitprice DECIMAL(10,2) NOT NULL DEFAULT 0 CHECK (unitprice >= 1.0 AND unitprice <= 9999.99),
    category INT NOT NULL DEFAULT 0,
    provider VARCHAR(64) NOT NULL DEFAULT ""
);

-- 客户表（customer）
CREATE TABLE customer (
    customer_id CHAR(8) PRIMARY KEY,
    name VARCHAR(64) NOT NULL DEFAULT '',
    address VARCHAR(64) NOT NULL DEFAULT '',
    email VARCHAR(64) UNIQUE NOT NULL,
    sex ENUM('男', '女') NOT NULL,
    card_id CHAR(18)
);

-- 购买表（purchase）
CREATE TABLE purchase (
    order_id INT UNSIGNED PRIMARY KEY,
    customer_id CHAR(8) NOT NULL,
    goods_id INT NOT NULL DEFAULT 0,
    nums INT NOT NULL DEFAULT 0,
    FOREIGN KEY (customer_id) REFERENCES customer(customer_id),
    FOREIGN KEY (goods_id) REFERENCES goods(goods_id)
);
```

## 自增长

### 基本介绍

在某张表中，有一个字段（id 列，整数类型），希望在添加记录时该列从 1 开始 **自动增长**。

语法：`字段名 整型 PRIMARY KEY AUTO_INCREMENT`

```sql
CREATE TABLE users (
    id INT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(50),
    email VARCHAR(100)
);

INSERT INTO users (name, email) VALUES ('Alice', 'alice@example.com');
```

### 使用细节

1. 一般来说，自增键是 **和 PRIMARY KEY 配合使用的**
2. 自增键也可以 **单独使用（但是需要配合一个 UNIQUE）**
3. 自增键修饰的字段为 **整型** 的（虽然小数也可以，但极少这样使用）
4. 自增键值 **默认从 1 开始**，可通过 `ALTER TABLE 表名 AUTO_INCREMENT = 新的开始值` 修改
5. 如果添加数据时 **给自增键字段指定了值，则以指定的值为准**

### 修改字段为自增长

前提：
- 该字段必须是整数类型（如 INT、BIGINT 等）
- 该字段通常需要设置为主键或至少是唯一索引
- 一个表中只能有一个 AUTO_INCREMENT 字段

```sql
ALTER TABLE table01 MODIFY COLUMN id INT AUTO_INCREMENT;
```

### 基于自增长的 INSERT 方法

```sql
INSERT INTO xxx (字段1, 字段2.....) VALUES(NULL, '值1', '值2'....);
INSERT INTO xxx (字段2....) VALUES('值1', '值2'....);
INSERT INTO xxx VALUES(NULL, '值1', ....);
```
