# 锁

---

## 基本介绍

锁是计算机协调 **多个进程或线程并发访问** 某一资源的机制。

在数据库中，除传统的计算资源（CPU、RAM、I/O）的争用以外，数据也是一种供许多用户共享的资源，如何保证数据 **并发访问的一致性**、有效性是所有数据库必须解决的一个问题。

MySQL 中的锁，按照锁的粒度分为以下三类：

- **全局锁**：锁定数据库中的所有表
- **表级锁**：每次操作锁住整张表
- **行级锁**：每次操作锁住对应的行数据

## 全局锁

### 基本介绍

全局锁就是 **对整个数据库实例加锁**，加锁后整个实例处于 **只读状态**，后续的 DML 写语句、DDL 语句以及已更新操作的事务提交语句都将被阻塞。

典型应用场景：做全库的逻辑备份，对所有表进行锁定，从而保证备份数据的完整性和一致性。

```sql
-- 加全局锁
FLUSH TABLES WITH READ LOCK;

-- 备份
mysqldump -u root -p --all-databases > backup.sql;

-- 释放锁
UNLOCK TABLES;
```

## 表级锁

### 表锁

表锁是最基本的锁策略，开销最小。表锁分为两类：

```sql
-- 表共享读锁（所有会话可读，不可写）
LOCK TABLES t1 READ;

-- 表独占写锁（当前会话可读写，其他会话不可读写）
LOCK TABLES t1 WRITE;

-- 释放所有锁
UNLOCK TABLES;
```

### 元数据锁（MDL）

MDL 是系统自动加的，不需要显式使用。主要作用是维护元数据的一致性，确保在表上有活动事务时，不能修改表结构。

| SQL 操作 | 加锁类型 | 说明 |
| -------- | -------- | ---- |
| SELECT | SHARED_READ | 共享读锁 |
| INSERT/UPDATE/DELETE | SHARED_WRITE | 共享写锁 |
| ALTER TABLE | EXCLUSIVE | 排他锁 |

### 意向锁

为了在加表锁时，不用逐行检查行锁而引入的锁。意向锁是 InnoDB 自动加的：

- **意向共享锁（IS）**：`SELECT ... LOCK IN SHARE MODE`
- **意向排他锁（IX）**：`INSERT / UPDATE / DELETE / SELECT ... FOR UPDATE`

| 锁类型 | IS | IX | S | X |
| ------ | -- | -- | - | - |
| IS | 兼容 | 兼容 | 兼容 | 不兼容 |
| IX | 兼容 | 兼容 | 不兼容 | 不兼容 |
| S | 兼容 | 不兼容 | 兼容 | 不兼容 |
| X | 不兼容 | 不兼容 | 不兼容 | 不兼容 |

## 行级锁

### 基本介绍

行级锁是 InnoDB 引擎中粒度最细的锁，每次操作锁住对应的行数据。InnoDB 的行锁是 **针对索引加的锁**，不是针对记录加的锁，并且该索引不能失效，否则行锁会升级为表锁。

### 行锁类型

**共享锁（S）**：允许事务读一行数据，但不允许修改。

```sql
SELECT ... LOCK IN SHARE MODE;
```

**排他锁（X）**：允许事务更新或删除一行数据。

```sql
-- 自动加排他锁
INSERT / UPDATE / DELETE

-- 手动加排他锁
SELECT ... FOR UPDATE;
```

### 间隙锁与临键锁

**间隙锁（Gap Lock）**：锁定一个范围，但不包含记录本身。防止其他事务在间隙中插入数据，解决幻读问题。

**临键锁（Next-Key Lock）**：行锁 + 间隙锁的组合，锁定一个范围并且包含记录本身。

InnoDB 默认使用 **临键锁** 来防止幻读，在 REPEATABLE READ 隔离级别下生效。

### 行锁升级为表锁

当 WHERE 条件中的字段没有索引时，行锁会升级为表锁：

```sql
-- id 有索引 → 行锁
UPDATE student SET no = '2000100100' WHERE id = 1;

-- name 没有索引 → 表锁，即使只更新一条也会锁全表！
UPDATE student SET no = '2000100100' WHERE name = '张三';
```
