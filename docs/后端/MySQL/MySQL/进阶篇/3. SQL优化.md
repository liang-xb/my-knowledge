# SQL 优化

---

## INSERT 优化

### 批量插入

**方案一：单次插入多条数据**

```sql
INSERT INTO tb_test VALUES(1,'Tom'),(2,'Cat'),(3,'Jerry');
```

**方案二：手动控制事务**

```sql
START TRANSACTION;
INSERT INTO tb_test VALUES(1,'Tom'),(2,'Cat'),(3,'Jerry');
INSERT INTO tb_test VALUES(4,'Tom'),(5,'Cat'),(6,'Jerry');
INSERT INTO tb_test VALUES(7,'Tom'),(8,'Cat'),(9,'Jerry');
COMMIT;
```

**方案三：主键顺序插入**

主键顺序插入的性能要高于乱序插入。

### 大量插入

大量插入数据时，可以使用 **LOAD** 指令，按指定格式读取信息：

```sql
LOAD DATA INFILE '/data/employee.txt' INTO TABLE employee
FIELDS TERMINATED BY ',' LINES TERMINATED BY '\n';
```

## 主键优化

### 页分裂与页合并

![页分裂](优化-1.png)

**页分裂：** 当数据页已满，需要插入新记录时，会将当前页分裂为两个新页，然后在合适位置插入数据。

**页合并：** 当删除数据后，相邻页可以合并成一个页，减少空间浪费。

### 主键设计原则

- 满足业务需求的情况下，尽量降低主键的长度
- 插入数据时，尽量选择顺序插入，选择使用 AUTO_INCREMENT 自增主键
- 尽量不要使用 UUID 做主键或者是其他自然主键，如身份证号
- 业务操作时，避免对主键的修改

## ORDER BY 优化

![ORDER BY优化](优化-2.png)

- Using filesort：通过表的索引或全表扫描，读取满足条件的数据行，然后在排序缓冲区 sort buffer 中完成排序操作，不是通过索引直接返回排序结果的排序
- Using index：通过有序索引顺序扫描直接返回有序数据，这种情况即为 Using index，不需要额外排序，操作效率高

**优化建议：**

- 根据排序字段建立合适的索引，多字段排序时，也遵循最左前缀法则
- 尽量使用覆盖索引
- 多字段排序，一个升序一个降序，此时需要注意联合索引在创建时的规则（ASC/DESC）
- 如果不可避免的出现 filesort，大数据量排序时，可以适当增大排序缓冲区大小 sort_buffer_size

## GROUP BY 优化

- 在分组操作时，可以通过索引来提高效率
- 分组操作时，索引的使用也是满足最左前缀法则的

## LIMIT 优化

当 LIMIT 分页较深时（如 `LIMIT 2000000,10`），MySQL 需要排序前 2000010 条记录，丢弃前 2000000 条，只返回最后 10 条，代价非常高。

**优化方案：**

```sql
-- 方案一：使用覆盖索引 + 子查询
SELECT a.* FROM tb_sku a
INNER JOIN (SELECT id FROM tb_sku ORDER BY id LIMIT 2000000,10) b
ON a.id = b.id;

-- 方案二：使用游标分页（记住上次最大的 ID）
SELECT * FROM tb_sku WHERE id > 2000000 LIMIT 10;
```

## COUNT 优化

![COUNT优化](优化-13.png)

MyISAM 引擎把一个表的总行数存在了磁盘上，执行 COUNT(\*) 时会直接返回。InnoDB 则需要逐行扫描。

COUNT 用法对比：

- **COUNT(*)**：统计总记录数（InnoDB 优化：找最小的非聚簇索引树遍历）
- **COUNT(主键)**：遍历整张表取出主键值（可能不走索引）
- **COUNT(字段)**：统计该字段不为 NULL 的记录数
- **COUNT(1)**：遍历整张表但不取值（InnoDB 会找最小的索引树）
- **COUNT(常量)**：等同于 COUNT(\*)

> 推荐：**COUNT(\*)**，InnoDB 对此做了优化。

## UPDATE 优化

InnoDB 的行锁是针对索引加的锁，不是针对记录加的锁，并且该索引不能失效，否则行锁会升级为表锁。

```sql
-- id 有索引 → 行锁
UPDATE student SET no = '2000100100' WHERE id = 1;

-- name 没有索引 → 表锁（即使只有一条记录）
UPDATE student SET no = '2000100100' WHERE name = '张三';
```

| 字段 | 说明 |
| ---- | ---- |

## SQL 提示

```sql
-- USE INDEX：建议使用指定索引
SELECT * FROM user USE INDEX(idx_name) WHERE name = 'tom';

-- IGNORE INDEX：忽略指定索引
SELECT * FROM user IGNORE INDEX(idx_name) WHERE name = 'tom';

-- FORCE INDEX：强制使用指定索引
SELECT * FROM user FORCE INDEX(idx_name) WHERE name = 'tom';
```
