# 主从复制

---

## 基本介绍

主从复制是指将主库的 **DDL 和 DML** 操作通过**二进制日志**传到从库，从库重新执行这些日志，使从库和主库数据保持同步。

MySQL 支持一台主库向多台从库复制，从库也可以作为其他服务器的主库，实现**链状复制**。

**主要优点：**

1. 主库故障时可快速切换到从库提供服务
2. 实现读写分离，降低主库访问压力
3. 可在从库执行备份，避免影响主库服务

## 实现原理

主从复制核心是**二进制日志**，分为三步：

1. **主库**：事务提交时，将数据变更记录写入 Binlog
2. **从库 I/O 线程**：读取主库 Binlog，写入从库的**中继日志 Relay Log**
3. **从库 SQL 线程**：重做 Relay Log 中的事件，反映到自身数据

## 环境搭建

### 准备工作

准备两台服务器（主/从），安装好 MySQL，关闭防火墙或开放 3306 端口。

### 主库配置

**（1）修改 `/etc/my.cnf`：**

```bash
server-id=1
read-only=0
# 需要同步的数据库（可选）
# binlog-do-db=db01
```

**（2）重启 MySQL：**

```bash
systemctl restart mysqld
```

**（3）创建远程连接账号并授予主从复制权限：**

```sql
CREATE USER 'itcast'@'%' IDENTIFIED WITH mysql_native_password BY 'Root@123456';
GRANT REPLICATION SLAVE ON *.* TO 'itcast'@'%';
```

**（4）查看二进制日志坐标：**

```sql
SHOW MASTER STATUS;
```

| 字段 | 说明 |
| ---- | ---- |
| File | 从哪个日志文件开始推送 |
| Position | 从哪个位置开始推送 |
| Binlog_Ignore_DB | 不需要同步的数据库 |

### 从库配置

**（1）修改 `/etc/my.cnf`：**

```bash
server-id=2
read-only=1
```

**（2）重启 MySQL 后，设置主库配置：**

```sql
-- MySQL 8.0.23+
CHANGE REPLICATION SOURCE TO
  SOURCE_HOST='192.168.200.200',
  SOURCE_USER='itcast',
  SOURCE_PASSWORD='Root@123456',
  SOURCE_LOG_FILE='binlog.000004',
  SOURCE_LOG_POS=663;

-- MySQL 8.0.23 之前
CHANGE MASTER TO
  MASTER_HOST='192.168.200.200',
  MASTER_USER='itcast',
  MASTER_PASSWORD='Root@123456',
  MASTER_LOG_FILE='binlog.000004',
  MASTER_LOG_POS=663;
```

**（3）开启同步并查看状态：**

```sql
START REPLICA;   -- 8.0.22+
START SLAVE;     -- 8.0.22 之前

SHOW REPLICA STATUS;   -- 8.0.22+
SHOW SLAVE STATUS;     -- 8.0.22 之前
```

### 测试

主库创建库表并插入数据，在从库中查询验证数据是否同步成功。
