# 分库分表

---

## 问题分析

随着数据量指数增长，单数据库存在以下性能瓶颈：

- **IO 瓶颈**：热点数据过多，缓存不足，大量磁盘 IO，请求数据过多导致网络 IO 瓶颈
- **CPU 瓶颈**：排序、分组、连接查询、聚合统计等消耗大量 CPU 资源

核心思路：将数据**分散存储**，使单一数据库/表的数据量变小，从而提升性能。

## 拆分策略

分库分表主要有两种形式：**垂直拆分**和**水平拆分**。

### 垂直拆分

**垂直分库**：以表为依据，根据业务将不同表拆分到不同库中。

特点：每个库的表结构不同、数据不同，所有库的并集是全量数据。

**垂直分表**：以字段为依据，将不同字段拆分到不同表中。

特点：每个表的结构不同，一般通过主键/外键关联，所有表的并集是全量数据。

### 水平拆分

**水平分库**：以字段为依据，将一个库的数据按策略拆分到多个库中。

特点：每个库的表结构相同，数据不同，所有库的并集是全量数据。

**水平分表**：以字段为依据，将一个表的数据按策略拆分到多个表中。

特点：每个表的结构相同，数据不同，所有表的并集是全量数据。

### 实现技术

| 技术 | 特点 |
| ---- | ---- |
| **ShardingSphere-JDBC** | 基于 AOP 原理，在应用层拦截 SQL，自行编码配置，仅支持 Java，性能较高 |
| **MyCat** | 数据库中间件，无需改代码即可实现分库分表，支持多种语言 |

## MyCat

### 基本介绍

Mycat 是基于 Java 语言编写的 MySQL 数据库中间件。开发人员只需连接 MyCat 即可，底层物理库的分布对开发者透明，分库分表策略只需在 MyCat 中配置。

### 目录结构

| 目录 | 说明 |
| ---- | ---- |
| `bin/` | 可执行文件，用于启动/停止 mycat |
| `conf/` | 配置文件（schema.xml, server.xml, rule.xml） |
| `lib/` | 项目依赖包（jar） |
| `logs/` | 日志文件 |

### 整体架构

- **逻辑结构**（上层）：逻辑库、逻辑表、分片规则、分片节点
- **物理结构**（下层）：实际的数据库服务器存储

### 核心配置文件

| 文件 | 作用 |
| ---- | ---- |
| `schema.xml` | 配置逻辑库、逻辑表、数据节点、节点主机 |
| `server.xml` | 配置用户名、密码、访问权限、系统参数 |
| `rule.xml` | 配置分片规则和分片算法 |

## schema.xml 配置详解

### schema 标签

定义逻辑库。一个 MyCat 实例可以有多个逻辑库，等同于 MySQL 中的 database。

| 属性 | 说明 |
| ---- | ---- |
| `name` | 自定义逻辑库库名 |
| `checkSQLschema` | SQL 中指定了库名时是否自动去除（true/false） |
| `sqlMaxLimit` | 未指定 limit 时最大查询行数 |

### table 标签

定义逻辑库下的逻辑表，所有需要拆分的表都要在此定义。

| 属性 | 说明 |
| ---- | ---- |
| `name` | 逻辑表表名，逻辑库下唯一 |
| `dataNode` | 所属数据节点，多个用逗号分隔 |
| `rule` | 分片规则名称，在 rule.xml 中定义 |
| `primaryKey` | 对应真实表的主键 |
| `type` | 表类型，`global` 表示全局表 |

### dataNode 标签

| 属性 | 说明 |
| ---- | ---- |
| `name` | 数据节点名称 |
| `dataHost` | 引用 dataHost 标签的 name 属性 |
| `database` | 分片所属的物理数据库 |

### dataHost 标签

定义具体的数据库实例、读写分离、心跳语句。

| 属性 | 说明 |
| ---- | ---- |
| `name` | 唯一标识 |
| `maxCon` / `minCon` | 最大/最小连接数 |
| `balance` | 负载均衡策略（0/1/2/3） |
| `writeType` | 写操作分发方式（0：第一个 writeHost，1：随机分发） |
| `dbDriver` | 数据库驱动，支持 native、jdbc |

## server.xml 配置详解

### system 标签

MyCat 系统配置信息，主要包括：

- 字符集、超时时间、SQL 统计等参数
- 实时统计开关 `useSqlStat`

### user 标签

配置用户、密码及权限信息：

```xml
<user name="root" defaultAccount="true">
    <property name="password">123456</property>
    <property name="schemas">DB01</property>
</user>

<user name="user">
    <property name="password">123456</property>
    <property name="schemas">DB01</property>
    <property name="readOnly">true</property>
</user>
```

## 分片规则

### 范围分片

根据字段值与数据节点范围的对应关系决定分片，适用于数字类型。

```xml
<!-- rule.xml -->
<tableRule name="auto-sharding-long">
    <rule>
        <columns>id</columns>
        <algorithm>rang-long</algorithm>
    </rule>
</tableRule>
```

映射文件 `autopartition-long.txt`：

```
0-500M=0
500M-1000M=1
1000M-1500M=2
```

### 取模分片

根据字段值与节点数量求模运算决定分片。

```xml
<function name="mod-long" class="io.mycat.route.function.PartitionByMod">
    <property name="count">3</property>
</function>
```

### 一致性 Hash 分片

相同哈希因子始终被划分到相同分区，有效解决分布式扩容问题。

```xml
<function name="murmur" class="io.mycat.route.function.PartitionByMurmurHash">
    <property name="seed">0</property>
    <property name="count">3</property>
    <property name="virtualBucketTimes">160</property>
</function>
```

### 枚举分片

在配置文件中配置枚举值，指定各值路由到不同节点。适用于按省份、性别、状态拆分。

```xml
<function name="hash-int" class="io.mycat.route.function.PartitionByFileMap">
    <property name="mapFile">partition-hash-int.txt</property>
</function>
```

`partition-hash-int.txt`：

```
1=0
2=1
3=2
```

### 应用指定算法

运行阶段由应用指定路由到哪个分片，根据字符子串计算分片号。

### 固定分片 Hash 算法

类似十进制求模但为二进制运算，连续值可能分配到相同分片，降低事务处理难度。分片字段必须是数字类型。

### 字符串 Hash 解析算法

截取字符串指定位置的子串进行 hash 计算分片。

### 按天分片算法

按日期及时间周期分片，每 N 天一个分片，到达结束时间后循环。

### 自然月分片

每个自然月为一个分片。

## 全局表

对于数据字典类表（如省市区），多个业务模块都可能引用，可设为全局表。全局表会在所有数据节点中创建副本：

```xml
<table name="tb_areas_provinces" dataNode="dn1,dn2,dn3" primaryKey="id" type="global"/>
```

全局表更新时，所有分片节点中的数据会同步变更。

## MyCat 管理与监控

### 端口

- **8066**：数据访问端口（DML/DDL 操作）
- **9066**：管理端口，用于管理 MyCat 集群状态

### MyCat 原理

执行 SQL 时，MyCat 经过 SQL 解析 → 分片分析 → 路由分析 → 读写分离分析，决定路由到哪些节点。数据库执行完毕后，MyCat 进行结果合并、聚合、排序、分页处理后返回给客户端。

### MyCat-eye（MyCat-Web）

MyCat 官方提供的可视化监控平台，依赖 ZooKeeper，主要功能：

- 管理 MyCat 的流量、连接、线程和内存
- IP 白名单、邮件告警
- SQL 统计、慢 SQL 和高频 SQL 分析

启动后访问：`http://<ip>:8082/mycat`

> 需要在 `server.xml` 中开启实时统计：`<property name="useSqlStat">1</property>`
