# 读写分离

---

## 基本介绍

读写分离是将读和写操作分开，路由到不同的数据库服务器：主库提供写操作，从库提供读操作，有效减轻单台数据库的压力。通过 MyCat 可轻松实现，支持 MySQL、Oracle 和 SQL Server。

## 一主一从

### 原理

基于 MySQL 主从复制（binlog）实现，主库处理写入，从库处理读取。

### schema.xml 配置

MyCat 的读写分离和负载均衡由 `dataHost` 标签的 `balance` 属性控制：

```xml
<dataNode name="dn7" dataHost="dhost7" database="itcast" />

<dataHost name="dhost7" maxCon="1000" minCon="10" balance="1" writeType="0"
          dbType="mysql" dbDriver="jdbc" switchType="1" slaveThreshold="100">
    <heartbeat>select user()</heartbeat>
    <writeHost host="master1" url="jdbc:mysql://192.168.200.211:3306?useSSL=false&..."
               user="root" password="1234">
        <readHost host="slave1" url="jdbc:mysql://192.168.200.212:3306?useSSL=false&..."
                  user="root" password="1234" />
    </writeHost>
</dataHost>
```

- `writeHost` 关联主库，处理写操作
- `readHost` 关联从库，处理读操作

### balance 参数

| 值 | 说明 |
| ---- | ---- |
| 0 | 不开启读写分离，所有读操作发送到当前可用的 writeHost |
| 1 | 全部 readHost 和 stand by writeHost 参与 select 负载均衡 |
| 2 | 所有读操作随机分发到 writeHost 和 readHost |
| 3 | 所有读请求随机分发到 writerHost 对应的 readHost 执行，writeHost 不负担读压力 |

一主一从模式中，balance 配置 1 或 3 都可以完成读写分离。

### 缺陷

当 Master 宕机后，业务系统只能读不能写。需要双主双从架构来解决。

## 双主双从

### 架构

Master1 处理所有写请求，Slave1、Master2 和 Slave2 负责所有读请求。Master1 宕机后，Master2 接管写请求。Master1 与 Master2 互为备机。

### 主库配置

**（1）Master1 (`server-id=1`) 的 `/etc/my.cnf`：**

```bash
server-id=1
binlog-do-db=db01
binlog-do-db=db02
binlog-do-db=db03
log-slave-updates
```

**（2）Master2 (`server-id=3`) 同样配置，server-id 改为 3。**

**（3）两台主库都创建复制账号并互相配置为主从：**

```sql
-- Master1 上指向 Master2
CHANGE MASTER TO MASTER_HOST='192.168.200.213', MASTER_USER='itcast',
MASTER_PASSWORD='Root@123456', MASTER_LOG_FILE='binlog.000002', MASTER_LOG_POS=663;

-- Master2 上指向 Master1
CHANGE MASTER TO MASTER_HOST='192.168.200.211', MASTER_USER='itcast',
MASTER_PASSWORD='Root@123456', MASTER_LOG_FILE='binlog.000002', MASTER_LOG_POS=663;

START SLAVE;
```

### 从库配置

Slave1 (`server-id=2`) 关联 Master1，Slave2 (`server-id=4`) 关联 Master2，`/etc/my.cnf` 仅需配置 `server-id`。

### 读写分离配置

```xml
<dataHost name="dhost7" maxCon="1000" minCon="10" balance="1" writeType="0"
          dbType="mysql" dbDriver="jdbc" switchType="1" slaveThreshold="100">
    <heartbeat>select user()</heartbeat>

    <writeHost host="master1" url="jdbc:mysql://192.168.200.211:3306..." user="root" password="1234">
        <readHost host="slave1" url="jdbc:mysql://192.168.200.212:3306..." user="root" password="1234" />
    </writeHost>

    <writeHost host="master2" url="jdbc:mysql://192.168.200.213:3306..." user="root" password="1234">
        <readHost host="slave2" url="jdbc:mysql://192.168.200.214:3306..." user="root" password="1234" />
    </writeHost>
</dataHost>
```

> `balance="1"`：所有 readHost 和 stand by writeHost 都参与 select 负载均衡。正常情况下 M2、S1、S2 都参与读操作。

### writeType 与 switchType

| 参数 | 值 | 说明 |
| ---- | ---- | ---- |
| writeType | 0 | 写操作转发到第一个 writeHost，挂了切第二个 |
| writeType | 1 | 写操作随机发送到配置的 writeHost |
| switchType | -1 | 不自动切换 |
| switchType | 1 | 自动切换 |
