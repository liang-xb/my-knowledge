# 日志

---

## 错误日志

错误日志记录了 `mysqld` 启动/停止时以及运行过程中发生的严重错误信息。数据库出现故障时，应首先查看此日志。

该日志**默认开启**，Linux 下默认存放在 `/var/log/mysqld.log`。

```sql
SHOW VARIABLES LIKE '%log_error%';
```

## 二进制日志 (BINLOG)

二进制日志记录了所有 **DDL** 和 **DML** 语句（不包括 SELECT、SHOW），主要作用：

1. **灾难恢复**：通过重放 binlog 恢复数据
2. **主从复制**：从库通过读取主库 binlog 实现同步

MySQL 8.0 中 binlog **默认开启**：

```sql
SHOW VARIABLES LIKE '%log_bin%';
```

| 参数 | 说明 |
| ---- | ---- |
| `log_bin_basename` | binlog 文件基础名称（前缀），具体文件在此基础上加编号（从 000001 开始） |
| `log_bin_index` | 索引文件，记录当前服务器关联的所有 binlog 文件 |

### 日志格式

通过 `binlog_format` 参数配置：

```sql
SHOW VARIABLES LIKE '%binlog_format%';
```

| 格式 | 说明 |
| ---- | ---- |
| STATEMENT | 记录 SQL 语句原文，日志量小，但某些函数（如 NOW()）可能导致主从不一致 |
| ROW | 记录每行数据变更细节，日志量大，但不会出现主从不一致（默认） |
| MIXED | 混合模式，大多数用 STATEMENT，特殊操作用 ROW |

### 查看

binlog 是二进制格式，需用 `mysqlbinlog` 工具查看：

```bash
mysqlbinlog [参数选项] logfilename
# 参数：
#   -d     只列出指定数据库的操作
#   -o     忽略日志中的前 n 行命令
#   -v     将行事件重构为 SQL 语句
#   -vv    重构为 SQL 并输出注释
```

### 删除

业务系统 binlog 增长很快，可通过以下方式清理：

- `RESET MASTER`：删除所有 binlog，重新编号
- `PURGE MASTER LOGS TO 'xxx'`：删除指定编号之前的日志
- `PURGE MASTER LOGS BEFORE 'yyyy-MM-dd'`：删除指定日期之前的日志

也可配置自动过期时间：

```sql
SHOW VARIABLES LIKE '%binlog_expire_logs_seconds%';
```

## 查询日志

查询日志记录客户端的所有操作语句（包含 SELECT），**默认未开启**。

在 `/etc/my.cnf` 中配置：

```bash
general_log=1
general_log_file=mysql_query.log
```

> 查询日志文件会非常大，生产环境不建议长期开启。

## 慢查询日志

慢查询日志记录执行时间超过 `long_query_time`（默认 10 秒）且扫描行数不小于 `min_examined_row_limit` 的 SQL。**默认未开启**。

在 `/etc/my.cnf` 中配置：

```bash
slow_query_log=1
long_query_time=2
# 记录管理语句慢查询
log_slow_admin_statements=1
# 记录未使用索引的慢查询
log_queries_not_using_indexes=1
```

> 以上配置修改后需重启 MySQL 服务器才能生效。
