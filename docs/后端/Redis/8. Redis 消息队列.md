# Redis 消息队列

---

## 基本介绍

消息队列（Message Queue）包含 3 个角色：

- **消息队列**：存储和管理消息，也被称为消息代理（Message Broker）
- **生产者**：发送消息到消息队列
- **消费者**：从消息队列获取并处理消息

![消息队列模型](55.png)

使用队列的好处在于 **解耦**。在秒杀场景中：下单后利用 Redis 校验下单条件，通过队列把消息发送出去，再启动一个线程去消费这个消息，完成解耦，同时加快响应速度。

我们可以使用现成的 MQ（Kafka、RabbitMQ 等），也可以直接使用 Redis 提供的 MQ 方案，降低部署和学习成本。

## 基于 List 实现消息队列

Redis 的 list 数据结构是双向链表，容易模拟队列效果。

利用 LPUSH 结合 RPOP（或 RPUSH 结合 LPOP）实现。注意当队列中没有消息时 RPOP 或 LPOP 操作会返回 null，应该使用 BRPOP 或 BLPOP 实现阻塞效果。

![List消息队列](56.png)

**优点：**

- 利用 Redis 存储，不受限于 JVM 内存上限
- 基于 Redis 的持久化机制，数据安全性有保证
- 可以满足消息有序性

**缺点：**

- 无法避免消息丢失（消费者取出消息后宕机）
- 只支持单消费者

## 基于 Pub/Sub 实现

Redis 发布订阅（Pub/Sub）是消息通信模式：发送者（PUBLISH）发送消息，订阅者（SUBSCRIBE）接收消息。

![PubSub](57.png)

```bash
# 订阅频道
SUBSCRIBE order.queue

# 发布消息
PUBLISH order.queue "新订单"
```

**优点：** 支持多生产者、多消费者

**缺点：** 不支持数据持久化、无法避免消息丢失、消息堆积有上限

## 基于 Stream 实现

Redis Stream 是 Redis 5.0 引入的新数据类型，专为消息队列设计，支持消息持久化、ACK 确认、消费者组等特性。

```bash
# 发送消息
XADD order.queue * name "jack" age 18

# 读取消息（从第一个开始，读取 2 条）
XREAD COUNT 2 STREAMS order.queue 0

# 阻塞读取最新消息
XREAD COUNT 1 BLOCK 5000 STREAMS order.queue $

# 创建消费者组
XGROUP CREATE order.queue group1 0

# 消费者组读取
XREADGROUP GROUP group1 consumer1 COUNT 1 BLOCK 5000 STREAMS order.queue >
```

**Java 代码实现：**

```java
// 生产者
@Component
public class StreamProducer {

    @Autowired
    private StringRedisTemplate stringRedisTemplate;

    public void sendOrderMsg(String msg) {
        Map<String, Object> map = new HashMap<>();
        map.put("msg", msg);
        stringRedisTemplate.opsForStream().add("order.queue", map);
    }
}

// 消费者
@Component
public class StreamConsumer {

    @Autowired
    private StringRedisTemplate stringRedisTemplate;

    @PostConstruct
    public void init() {
        new Thread(() -> {
            while (true) {
                try {
                    List<MapRecord<String, Object, Object>> records =
                        stringRedisTemplate.opsForStream().read(
                            Consumer.from("group1", "consumer1"),
                            StreamReadOptions.empty().count(1).block(Duration.ofSeconds(5)),
                            StreamOffset.create("order.queue", ReadOffset.lastConsumed())
                        );
                    if (records != null && !records.isEmpty()) {
                        // 处理消息
                        for (MapRecord<String, Object, Object> record : records) {
                            Map<Object, Object> value = record.getValue();
                            stringRedisTemplate.opsForStream()
                                    .acknowledge("order.queue", "group1", record.getId());
                        }
                    }
                } catch (Exception e) {
                    // 处理未 ACK 的 Pending 消息
                    handlePendingMessages();
                }
            }
        }).start();
    }
}
```

## 三种方案对比

| 对比项 | List | Pub/Sub | Stream |
| ------ | ---- | ------- | ------ |
| 消息持久化 | 支持 | 不支持 | 支持 |
| ACK 确认 | 不支持 | 不支持 | 支持 |
| 消费者组 | 不支持 | 不支持 | 支持 |
| 消息堆积 | 不受限 | 有上限 | 不受限 |
| 适用场景 | 简单场景 | 实时广播 | 企业级消息队列 |
