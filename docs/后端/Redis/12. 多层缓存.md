# 多层缓存

---

## 为什么需要多层缓存

![单层缓存问题](109.png)

存在如下两个问题：

1. 请求要经过 Tomcat 处理，Tomcat 的性能成为整个系统的瓶颈
2. Redis 缓存失效时，会对数据库产生冲击

## 多层缓存架构

![多层缓存架构](108.png)

多级缓存就是充分利用请求处理的每个环节，分别添加缓存，减轻 Tomcat 压力，提升服务性能：

1. 浏览器访问静态资源时，优先读取浏览器本地缓存
2. 访问非静态资源（ajax 查询数据）时，访问服务端
3. 服务端先查 Nginx 本地缓存（OpenResty + Lua）
4. Nginx 缓存未命中，查 Redis 缓存
5. Redis 未命中，查 JVM 进程内缓存（如 Caffeine）
6. JVM 缓存未命中，查询数据库

## OpenResty

### 基本介绍

OpenResty 是一个基于 Nginx 和 Lua 的高性能 Web 平台，集成了大量 Lua 库，方便搭建高并发、高可扩展的 Web 服务。

官网：https://openresty.org/cn/

### 安装

```bash
# CentOS
yum install -y pcre-devel openssl-devel gcc curl
wget https://openresty.org/download/openresty-1.21.4.1.tar.gz
tar -zxvf openresty-1.21.4.1.tar.gz
cd openresty-1.21.4.1
./configure
make && make install
```

### Nginx 配置

```nginx
# nginx.conf
http {
    # 引入 Lua 模块
    lua_package_path "/usr/local/openresty/lualib/?.lua;;";
    lua_package_cpath "/usr/local/openresty/lualib/?.so;;";

    server {
        listen 8081;

        location /api/ {
            # 通过 Lua 访问 Redis
            content_by_lua_block {
                local redis = require "resty.redis"
                local red = redis:new()
                red:set_timeouts(1000, 1000, 1000)

                local ok, err = red:connect("127.0.0.1", 6379)
                if not ok then
                    ngx.say("failed to connect: ", err)
                    return
                end

                -- 查询缓存
                local value, err = red:get("cache:key")
                if value == ngx.null then
                    -- 缓存未命中，代理到后端
                    ngx.exec("@backend")
                else
                    ngx.say(value)
                end
            }
        }

        location @backend {
            proxy_pass http://backend_server;
        }
    }
}
```

## Caffeine（JVM 缓存）

### 基本介绍

Caffeine 是一个高性能的 Java 本地缓存库，性能远优于 Guava Cache。

```xml
<dependency>
    <groupId>com.github.ben-manes.caffeine</groupId>
    <artifactId>caffeine</artifactId>
</dependency>
```

### 基本使用

```java
// 创建缓存
Cache<String, Object> cache = Caffeine.newBuilder()
        .maximumSize(1000)           // 最大容量
        .expireAfterWrite(10, TimeUnit.MINUTES)  // 写入后过期
        .build();

// 存入
cache.put("key", value);

// 取出
Object value = cache.getIfPresent("key");

// 不存在时自动加载
Object value = cache.get("key", k -> {
    // 查数据库
    return queryFromDB(k);
});
```

## 缓存同步策略

### 数据库变更如何同步缓存

**方案一：通过 Canal 监听 MySQL 变更**

Canal 是阿里巴巴开源的 MySQL binlog 增量订阅&消费组件，可以模拟 MySQL slave 的交互协议，获取 binlog 并解析。

数据变更流程：MySQL 写入 → Canal 监听 binlog → RabbitMQ/Kafka → 消费端更新缓存

**方案二：主动通知**

在业务代码中，数据库变更后主动发送 MQ 消息通知缓存更新：

```java
@Transactional
public void updateShop(Shop shop) {
    // 1. 更新数据库
    shopMapper.updateById(shop);
    // 2. 删除 Redis 缓存
    stringRedisTemplate.delete("cache:shop:" + shop.getId());
    // 3. 发送 MQ 通知
    rabbitTemplate.convertAndSend("cache.sync.exchange", "shop", shop.getId());
}
```

**方案三：设置 TTL**

最简单的方案，给缓存设置合理的 TTL，容忍短时间的数据不一致。
