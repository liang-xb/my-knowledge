# Spring IOC 与 DI

---

## 基本概念

### IOC（控制反转）

**IOC（Inversion of Control）** 是 Spring 框架的核心思想。它将对象的创建权由程序自身反转到外部容器，由 Spring 的 IOC 容器来创建和管理对象。

传统的对象创建方式是由开发者手动 `new` 对象：

```java
// 传统方式：程序主动创建依赖对象
UserService userService = new UserServiceImpl();
```

使用 IOC 后，对象的创建由 Spring 容器负责，程序被动接收：

```java
// IOC 方式：容器创建对象并注入
@Autowired
private UserService userService;
```

**IOC 的优势：**
- 降低代码之间的耦合度
- 资源集中管理，便于配置和修改
- 提高代码的可测试性

### DI（依赖注入）

**DI（Dependency Injection）** 是 IOC 思想的具体实现方式。容器在运行期间，动态地将某个依赖对象注入到当前对象中。

常见的注入方式：

| 注入方式 | 注解 | 说明 |
| -------- | ---- | ---- |
| 属性注入 | `@Autowired` | 最常用，通过反射注入字段 |
| 构造器注入 | `@Autowired` + 构造方法 | 推荐方式，依赖不可变 |
| Setter 注入 | `@Autowired` + setter | 可选依赖场景适用 |

## Spring 容器

### Bean 的定义

在 Spring 中，被 IOC 容器管理的对象称为 **Bean**。通过以下注解将类声明为 Bean：

| 注解 | 说明 | 使用场景 |
| ---- | ---- | -------- |
| `@Component` | 通用组件注解 | 工具类等通用组件 |
| `@Service` | 标识服务层 Bean | Service 层 |
| `@Repository` | 标识数据访问层 Bean | Dao/Mapper 层 |
| `@Controller` | 标识控制器 Bean | Controller 层 |

```java
@Service
public class UserServiceImpl implements UserService {
    @Autowired
    private UserMapper userMapper;
}
```

### Bean 的作用域

Spring 中 Bean 的作用域通过 `@Scope` 注解来指定：

```java
@Scope("singleton")  // 单例（默认）：整个容器中只有一个实例
@Scope("prototype")  // 原型：每次获取都会创建新的实例
```

### Bean 的生命周期

Bean 的生命周期由 Spring 容器管理：

1. **实例化**：通过反射创建 Bean 实例
2. **属性注入**：为 Bean 的属性注入依赖（`@Autowired`）
3. **初始化**：执行 `@PostConstruct` 标记的初始化方法
4. **使用**：Bean 就绪，可供应用程序使用
5. **销毁**：容器关闭时，执行 `@PreDestroy` 标记的销毁方法

```java
@Service
public class UserService {

    @PostConstruct
    public void init() {
        System.out.println("Bean 初始化完成");
    }

    @PreDestroy
    public void destroy() {
        System.out.println("Bean 即将销毁");
    }
}
```

## 依赖注入详解

### @Autowired

`@Autowired` 是 Spring 提供的最常用的依赖注入注解，默认按照 **类型（byType）** 自动装配。

```java
@RestController
public class UserController {

    @Autowired  // 按类型注入
    private UserService userService;
}
```

### @Qualifier

当同一个接口有多个实现类时，配合 `@Qualifier` 按 **名称（byName）** 指定注入的 Bean：

```java
@RestController
public class UserController {

    @Autowired
    @Qualifier("userServiceImpl2")
    private UserService userService;
}
```

### @Resource

`@Resource` 是 JDK 提供的注解，默认按照 **名称** 注入，找不到再按类型：

```java
@RestController
public class UserController {

    @Resource(name = "userServiceImpl")
    private UserService userService;
}
```

| 对比项 | @Autowired | @Resource |
| ------ | ---------- | --------- |
| 来源 | Spring 框架 | JDK（javax.annotation） |
| 默认方式 | 按类型（byType） | 按名称（byName） |
| 是否必须 | required 属性控制 | 默认必须 |

## 配置类

### @Configuration

使用 Java 配置类替代 XML 配置，通过 `@Configuration` 和 `@Bean` 声明：

```java
@Configuration
public class AppConfig {

    @Bean
    public UserService userService() {
        return new UserServiceImpl();
    }

    @Bean
    public DataSource dataSource() {
        DruidDataSource ds = new DruidDataSource();
        ds.setUrl("jdbc:mysql://localhost:3306/db");
        ds.setUsername("root");
        ds.setPassword("123456");
        return ds;
    }
}
```

### @ComponentScan

指定 Spring 容器扫描的包路径，默认扫描启动类所在包及其子包：

```java
@SpringBootApplication
@ComponentScan(basePackages = "com.example")
public class Application {
    public static void main(String[] args) {
        SpringApplication.run(Application.class, args);
    }
}
```

## @Conditional 条件装配

根据条件来决定是否创建 Bean，常用于自动配置场景：

```java
@Configuration
public class ConditionalConfig {

    @Bean
    @ConditionalOnClass(name = "com.mysql.cj.jdbc.Driver")
    public DataSource mysqlDataSource() {
        // 只有 MySQL 驱动存在时才创建
        return new DruidDataSource();
    }
}
```

## 总结

- **IOC** 是思想，把对象创建控制权交给容器
- **DI** 是 IOC 的实现，在运行时将依赖注入对象
- `@Autowired` 按类型注入，`@Resource` 按名称注入
- `@Service` / `@Repository` / `@Controller` 都是 `@Component` 的衍生注解
- Java 配置类（`@Configuration` + `@Bean`）替代 XML 配置
