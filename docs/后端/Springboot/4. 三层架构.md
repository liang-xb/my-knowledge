# 三层架构

---

## 为什么需要分层

当逻辑复杂时，所有代码都写在 Controller 中会导致复用性差、难以维护。修改数据操作、业务逻辑或响应逻辑都需要改动 Controller。

## 三大层

| 层 | 职责 |
| ---- | ---- |
| **Controller**（控制层） | 接收前端请求，处理请求，响应数据 |
| **Service**（业务逻辑层） | 处理具体的业务逻辑 |
| **Dao**（数据访问层/持久层） | 数据访问操作，包括增、删、改、查 |

### 调用逻辑

```
前端请求 → Controller → Service → Dao → 数据
              ↑          ↑        ↑
              响应      返回结果   返回数据
```

### 优势

1. 复用性强
2. 便于维护
3. 利于扩展

## 代码示例

### Controller 层

```java
@RestController
public class UserController {
    private UserService userService = new UserServiceImpl();

    @RequestMapping("/list")
    public List<User> list() {
        return userService.findAll();
    }
}
```

### Service 层（接口 + 实现）

```java
public interface UserService {
    List<User> findAll();
}

public class UserServiceImpl implements UserService {
    private UserDao userDao = new UserDaoImpl();

    @Override
    public List<User> findAll() {
        List<String> lines = userDao.findAll();
        return lines.stream().map(line -> {
            String[] parts = line.split(",");
            // ... 解析封装为 User 对象
            return new User(id, username, password, name, age, updateTime);
        }).collect(Collectors.toList());
    }
}
```

### Dao 层（接口 + 实现）

```java
public interface UserDao {
    List<String> findAll();
}

public class UserDaoImpl implements UserDao {
    @Override
    public List<String> findAll() {
        InputStream in = this.getClass().getClassLoader()
                .getResourceAsStream("user.txt");
        return IoUtil.readLines(in, StandardCharsets.UTF_8, new ArrayList<>());
    }
}
```
