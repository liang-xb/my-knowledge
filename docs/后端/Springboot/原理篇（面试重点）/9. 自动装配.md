# 自动装配

---

## 起步依赖原理

起步依赖的原理就是 **Maven 的依赖传递**。例如 `spring-boot-starter-web` 内部集成了 json、webmvc、tomcat 等依赖，只需引入一个起步依赖，其他依赖都会通过 Maven 传递进来。

官网：<https://docs.spring.io/spring-boot/docs/2.7.7/reference/htmlsingle/#using.build-systems.starters>

## 自动配置

SpringBoot 启动后，**一些配置类、bean 对象自动存入 IoC 容器**，不需要手动声明。

### 问题引入

引入第三方依赖后，发现依赖中的 `@Component` 注解不生效，因为 SpringBoot 的 `@SpringBootApplication` **只会扫描启动类所在包及其子包**，第三方依赖的包路径不在扫描范围内。

### 解决方案

**方案一：@ComponentScan 组件扫描**

```java
@SpringBootApplication
@ComponentScan({"com.itheima", "com.example"})
public class SpringbootWebConfigApplication { ... }
```

> 缺点：使用繁琐，需要为每个第三方依赖配置扫描路径，大范围扫描性能低。SpringBoot **并没有采用此方案**。

**方案二：@Import 导入**

三种导入形式：
- 导入普通类
- 导入配置类
- 导入 `ImportSelector` 接口实现类

```java
// 导入普通类
@Import(TokenParser.class)
@SpringBootApplication
public class SpringbootWebConfigApplication { ... }

// 导入配置类
@Import(HeaderConfig.class)
@SpringBootApplication
public class SpringbootWebConfig2Application { ... }
```

### 优化：@EnableXxx 注解

让第三方依赖自己指定要导入的 bean 和配置类，封装为 `@EnableXxx` 注解，这是 **SpringBoot 采用的方式**：

```java
@Target(ElementType.TYPE)
@Retention(RetentionPolicy.RUNTIME)
@Import(MyImportSelector.class)
public @interface EnableHeaderConfig {}
```

使用时只需在启动类加 `@EnableHeaderConfig` 即可。
