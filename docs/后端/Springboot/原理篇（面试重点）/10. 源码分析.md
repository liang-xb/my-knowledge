# 源码分析

---

## 源码跟踪技巧

跟踪框架源码要**抓住关键点，找到核心流程**，从宏观上理解原理，不要逐行深入研究。有精力再研究细节。

## @SpringBootApplication

`@SpringBootApplication` 是 SpringBoot 自动配置的核心入口，包含三个关键注解：

### 1. @SpringBootConfiguration

声明启动类是一个**配置类**（内含 `@Configuration`）。

### 2. @ComponentScan

进行**组件扫描**，扫描启动类所在包及其子包下被 `@Component` 及其衍生注解声明的类。

### 3. @EnableAutoConfiguration（核心）

- 封装了 `@Import` 注解，导入 `AutoConfigurationImportSelector`（实现了 `ImportSelector` 接口）
- 重写的 `selectImports()` 方法会读取所有依赖 jar 包中的 **`META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports`** 文件
- 该文件中定义了所有自动配置类的全类名
- SpringBoot 启动时加载这些配置类到 IoC 容器中

> 低版本（2.7.8 以前）SpringBoot 中，自动配置类定义在 `spring.factories` 文件中。

## @Conditional 条件装配

`META-INF/spring/...AutoConfiguration.imports` 中定义了大量的配置类，但**并非所有 bean 都会注册到 IoC 容器**。通过 `@Conditional` 系列注解按条件装配：

| 注解 | 说明 |
| ---- | ---- |
| `@ConditionalOnClass` | 环境中有对应字节码文件，才注册 bean |
| `@ConditionalOnMissingBean` | 环境中没有对应类型的 bean，才注册 |
| `@ConditionalOnProperty` | 配置文件中有对应属性和值，才注册 |

```java
@Bean
@ConditionalOnClass(name = "io.jsonwebtoken.Jwts")  // 存在该类才注册
public HeaderParser headerParser() { return new HeaderParser(); }

@Bean
@ConditionalOnMissingBean  // 不存在该类型 bean 才注册
public HeaderParser headerParser() { return new HeaderParser(); }

@Bean
@ConditionalOnProperty(name = "name", havingValue = "itheima")  // 配置文件匹配才注册
public HeaderParser headerParser() { return new HeaderParser(); }
```

## 自动配置原理总结

1. `@SpringBootApplication` → `@EnableAutoConfiguration` → `@Import(AutoConfigurationImportSelector.class)`
2. `selectImports()` 方法读取 `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` 配置文件
3. 加载文件中定义的所有配置类到 IoC 容器
4. 配置类中通过 `@Conditional` 系列注解**按条件**选择性注册 bean
