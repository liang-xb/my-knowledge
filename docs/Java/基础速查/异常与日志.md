# <center>异常与日志</center>

---

## 异常体系

```
Throwable
├── Error（严重问题，不处理，如 OutOfMemoryError）
└── Exception
    ├── RuntimeException（运行时异常，可以不 try-catch）
    │   ├── NullPointerException    空指针
    │   ├── IndexOutOfBoundsException  索引越界
    │   ├── IllegalArgumentException    参数非法
    │   └── ArithmeticException      除零等
    └── 编译时异常（必须 try-catch 或 throws）
        ├── IOException
        ├── SQLException
        └── FileNotFoundException
```

---

## try-catch-finally

```java
try {
    // 可能出错的代码
    int result = 10 / 0;
} catch (ArithmeticException e) {
    // 捕获特定异常
    System.out.println("除数不能为 0");
    e.printStackTrace();  // 打印堆栈，调试用
} catch (Exception e) {
    // 兜底捕获
} finally {
    // 无论是否异常都会执行（释放资源）
}
```

### try-with-resources（Java7+，推荐）

```java
// 自动关闭资源，无需手动 finally
try (FileInputStream fis = new FileInputStream("test.txt");
     BufferedReader reader = new BufferedReader(new InputStreamReader(fis))) {
    String line = reader.readLine();
} catch (IOException e) {
    e.printStackTrace();
}
// fis 和 reader 会自动调用 close()
```

## throw vs throws

```java
// throws：声明方法可能抛出的异常（甩锅给调用者）
public void readFile(String path) throws IOException {
    // ...
}

// throw：手动抛出一个异常对象
public void setAge(int age) {
    if (age < 0) {
        throw new IllegalArgumentException("年龄不能为负数");
    }
    this.age = age;
}
```

## 自定义异常

```java
// 业务异常
public class BusinessException extends RuntimeException {
    private int code;

    public BusinessException(int code, String message) {
        super(message);
        this.code = code;
    }

    public int getCode() { return code; }
}

// 使用
if (user == null) {
    throw new BusinessException(401, "用户不存在");
}
```

## 最佳实践

1. **不要吞异常** — `catch` 后至少打日志，不要空着
2. **精确捕获** — 先捕获具体的，再捕获宽泛的
3. **异常要带上下文** — `throw new RuntimeException("用户ID=" + id + " 查询失败", e)` 方便排查
4. **不要用异常控制业务流程** — 异常是意外情况，正常逻辑用 if-else

## 日志框架

### 选型

| 年代 | 方案 |
|------|------|
| 老旧项目 | Log4j |
| 过渡期 | SLF4J + Logback |
| **现代项目（推荐）** | SLF4J + Logback（SpringBoot 默认） |
| 最新趋势 | SLF4J + Log4j2 |

### 基本使用

```java
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

public class UserService {
    private static final Logger log = LoggerFactory.getLogger(UserService.class);

    public void doSomething(Long userId) {
        log.info("开始处理用户, userId={}", userId);

        try {
            // 业务逻辑
            log.debug("处理完成, result={}", result);
        } catch (Exception e) {
            log.error("处理失败, userId={}", userId, e);  // 最后一个参数传异常对象
        }
    }
}
```

### 日志级别

```
TRACE < DEBUG < INFO < WARN < ERROR
```

| 级别 | 用途 |
|------|------|
| DEBUG | 开发调试信息 |
| INFO | 业务流程关键节点（默认级别） |
| WARN | 潜在问题，不影响业务 |
| ERROR | 错误，需要关注和处理 |

### 注意事项

- **不要用 `System.out.println`** — 无法控制级别，无法输出到文件
- **日志用 `{}` 占位符** — 不要用字符串拼接，影响性能
- **敏感信息脱敏** — 手机号、密码、身份证不要原样打印
- **生产环境用 INFO 级别** — DEBUG 会产生大量日志

## application.yml 日志配置（SpringBoot）

```yaml
logging:
  level:
    root: INFO
    com.yourpackage: DEBUG      # 自己的包可以开 DEBUG
  file:
    path: ./logs                 # 日志文件路径
```
